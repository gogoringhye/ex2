ABOUT THE PRACTICE

02 / 06

화면을 만드는 일은
구조를 이해하는 데서 시작합니다.

운영의 맥락까지
생각하는 퍼블리싱.

좋은 퍼블리싱은 시안을 화면으로 옮기는 데서 끝나지 않습니다. 콘텐츠의 의미와 사용자 흐름을 살리고, 다양한 환경에서 읽기 쉽게 작동하며, 이후 수정도 고려한 코드로 구현하는 과정이라고 생각합니다.

운영·유지보수에 대한 관점은 이 포트폴리오에서 구현 원칙과 점검 흐름으로 다룹니다. 실제 경력이나 프로젝트 사례는 확인 가능한 내용으로 보강할 예정입니다.

CAPABILITIES / 03

기술보다 먼저,
구현의 기준을 세웁니다.

아래 역량은 현재 포트폴리오 코드에서 확인할 수 있는 구현을 바탕으로 정리했습니다. 실제 작업 사례의 상세 근거는 추가 확인이 필요합니다.

01 / STRUCTURE

의미 있는 문서 구조

랜드마크와 제목 위계를 사용해 콘텐츠 흐름을 명확히 하고, 기본 HTML 동작을 우선합니다.

HTML5 · SEMANTICS
이 페이지에서 보기 ＋

헤더·메인·푸터 랜드마크, 섹션별 제목 연결, 네이티브 링크와 details 요소를 사용합니다.

02 / RESPONSIVE

유연한 화면 구성

Grid와 Flexbox, 반응형 브레이크포인트로 화면 폭에 따라 콘텐츠 순서와 읽기 흐름을 조정합니다.

CSS · GRID · FLEXBOX
이 페이지에서 보기 ＋

프로젝트마다 다른 그리드 배치와 태블릿·모바일 브레이크포인트를 적용합니다.

03 / INTERACTION

목적이 분명한 동작

메뉴, 프로젝트 분류와 상세 정보에 필요한 JavaScript를 연결하고 상태를 접근성 속성으로 전달합니다.

VANILLA JS · DOM
이 페이지에서 보기 ＋

모바일 메뉴, 필터 상태, 스크롤 진입 애니메이션과 키보드 조작을 지원합니다.

04 / QUALITY

확인 가능한 품질

키보드 포커스, reduced motion 설정, 작은 화면에서의 탐색을 고려한 구현을 적용합니다.

A11Y · QA · MAINTENANCE
이 페이지에서 보기 ＋

명확한 focus-visible 스타일, prefers-reduced-motion 대응과 화면 폭별 표시를 확인할 수 있습니다.

MAINTENANCE APPROACH / 05

문제를 살피고,
수정 후 다시 확인합니다.

실제 유지보수 이력을 주장하는 항목이 아니라, 기존 웹사이트 개선에 적용할 점검 흐름입니다. 실제 사례는 확인 후 추가합니다.

  1. 01

    문제 상황 기록

    재현 경로, 환경과 기대 결과를 구체적으로 확인합니다.

    OBSERVE
  2. 02

    원인과 영향 범위 파악

    연결된 컴포넌트와 화면을 살펴 필요한 수정 범위를 정합니다.

    ANALYZE
  3. 03

    수정 후 회귀 확인

    주요 뷰포트와 키보드 흐름을 다시 점검해 의도치 않은 변화를 확인합니다.

    VERIFY
  4. 04

    변경 내용 공유

    수정 이유와 영향, 남은 확인 사항을 기록해 후속 작업에 연결합니다.
